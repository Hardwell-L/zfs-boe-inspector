# 本地 Markdown 知识库（第二版）

## 使用流程

1. 在 AI 分析的“知识库”页选择 `.md` 文件。支持多文件导入，可选填适用 BOE 版本；导入不调用模型。
2. 在分析会话勾选“使用本地知识库”，照常选择字段、区域或过程并输入问题。
3. 如需手动调整，可先在“范围与证据 → 参考文档”检索、查看原文并勾选章节，也可使用配置键或章节名称补充检索。
4. 点击“发送”：自动刷新单据证据，按需在本机检索相关章节，完成脱敏和大小检查后直接调用模型，不再要求二次确认。
5. 回答生成后可通过“查看依据”核对本次实际发送的单据证据和参考片段。“查看发送内容”仍是可选查看入口，不阻塞发送。

未启用知识库的会话维持原有直接发送行为。知识库可在没有单据快照时导入管理，但本版问答仍要求单据分析范围或所选过程。

## 导入与存储

UTF-8 解码、内容摘要、Markdown 解析及章节建索引在独立 Worker 中完成；Worker 随扩展打包，不访问远程服务。每个文件完成后终止 Worker，失败、取消或超过 60 秒也会终止。原始 UTF-8 Markdown、文档目录、章节索引、章节正文分别保存在扩展源的 IndexedDB 中。启动时只读取目录；检索逐项扫描索引，只加载候选正文，不加载全部原文。更新或删除文档使用跨存储事务；写入失败时旧版本不会被部分覆盖。每个文件单独提交，批量导入会报告逐文件结果。可取消进行中的导入；尚未提交的写入回滚，已经提交的文件保留，后续文件不再处理。关闭面板也会取消进行中的导入。

SHA-256 与适用版本共同用于去重；同名不同内容不会自动覆盖，需要点击目标文档的“选择文件更新”。适用版本可使用 `boe_version` 元信息或导入输入框。输入框非空时优先。目前仅支持逗号分隔的精确版本，不解析 `>=`、`^` 或 `384+` 等范围表达式。

支持简单单行 front matter：`title`、`source_url` / `source`、`boe_version`。这不是完整 YAML 解析器，多行元信息需在导入前整理。文档自身的 `version` 不作为 BOE 版本。原文不自动总结、润色或纠正业务规则。

解析 ATX 标题（`#` 至 `######`），跳过代码围栏中的伪标题，保留表格和完整代码。目录、写在最后、相关源码索引不进入检索正文，但仍保留在原文中。未闭合代码围栏和 front matter 会拒绝导入；图片只提示补充文字，不做 OCR、不下载图片、不追踪外链。

## 初始限制

| 项目 | 限制 |
| --- | --- |
| 单文件 | 2,000,000 字节 |
| 单次导入 | 20 个文件，合计 10,000,000 字节 |
| 文档总数 | 200 篇 |
| 原文累计 | 20,000,000 字节，不含索引及章节副本 |
| 每篇章节 | 5,000 个 |
| 检索候选 | 最多 30 个，关联可额外补充最多 12 个 |
| 自动选入 | 前 6 个主章节及其已解析的一层关联作为分组，受 20 KB 总预算约束 |
| 关联展开 | 每个主章节最多 16 个明确章节号，每个章节号最多前 6 个子章节，不递归 |
| 单次文档证据 | 20,000 字节，按脱敏后的证据 JSON 计算 |

阈值集中在 `knowledge.ts` 中，是初始保护值，不代表已验证的容量或性能承诺。手动选择也受文档预算限制。完整请求继续受 AI 设置的总请求体限制；本版没有模型 tokenizer，不把字节限制等同于模型 token 上限。章节太长时提示用户补充子标题，不静默裁剪例外或代码。索引和章节会额外占用磁盘空间，浏览器存储不足时报告失败。

## 检索与引用

问题词采用英文标识符、中文双字词匹配，补充少量业务同义词。第二版区分原问题词、同义词、背景配置键：用户明确写出的标识符优先，当前小节标题命中加权；同义词和背景配置的分数有上限，按词汇长度和问题覆盖率调整排序，减少长章节因词多而占优。父标题不再为所有子章节提供相同标题加分。这是确定性加权关键词检索，并非 BM25、向量检索或模型重排。没有可靠命中时允许空结果，用户可改用具体配置键或章节名补选。

当前 BOE 版本来自快照 `meta.zfsPackages['@zfs/boe']`。版本明确不匹配时排除；任一方未知时允许候选，但显示需人工核对。第二版解析 `§19`、`§9.2`、`见第 19 章` 等明确数字章节引用，仅在同一篇文档内展开一层，引用整章时按原文顺序补充其子章节。不会追踪外链或读取代码围栏内的引用。未找到正文、超过关联限制和未递归展开的引用会明确显示；没有明确引用的隐含依赖仍需人工补充。正文和已解析关联按组计算预算，放不下时不截断或偷偷丢掉关联章节。用户手动取消关联章节时，缺口会写入请求，模型不得将规则视为已完整核实。

文档使用 `[K编号]`，单据证据沿用 `[E编号]`。请求中包含文档来源、章节路径、原文行号、适用版本和内容摘要标识，以及实际选入的关联证据编号、未选入的关联章节和未展开引用。文档与单据证据都经过现有脱敏器；脱敏并不保证覆盖所有自定义信息，可在发送前通过可选查看入口核对内容。

文档仅作为资料，不能成为模型操作指令。渲染使用现有受限 Markdown 组件，不执行 HTML、链接和图片。文档声明不能替代运行时证据。

## 一致性与生命周期

- 每个会话有独立的候选、勾选状态和检索词；问题或配置检索条件变化会重新检索，恢复推荐选择并提示。
- 检索绑定活动请求，停止或切换页面导致请求失效后不回填结果。
- 发送准备阶段检查知识库目录版本；其他面板更新、删除文档后重新检索，检索过程中发生变化则报错要求重试。
- 发送前完成刷新、检索和大小检查，随后冻结本次实际请求用于回答引用；不保留待确认的预览状态。
- 当前面板中的回答保留实际发送的脱敏片段，即使文档随后更新也能核对。本机问答历史继续只保存问答白名单，不新增单据证据或参考片段持久化；关闭面板后不能依靠历史重建原始引用。
- 卸载扩展或清理扩展数据可能删除知识库，请保留原始 Markdown 备份。

## 旧数据兼容

不改变 IndexedDB 数据库版本，不清空已有文档。新导入的索引额外保存标题路径和明确章节引用；旧索引缺少这些可选字段时，从已有标题路径及候选正文解析，不要求强制重新导入。没有分隔信息的旧标题路径可能无法精确区分标题自身的斜杠，重新导入可获得完整结构。

## 验证范围与后续

第二版按项目技能约束只执行改动文件的 ESLint 和 diff 检查。尚未进行浏览器 IndexedDB、模型发送或性能实测，也未运行 test、typecheck、build。

后续验收应覆盖：重复导入、事务写入失败、版本过滤、跨面板更新、取消检索、实际发送证据冻结、超限不截断、表格及代码保真，以及小/中/接近上限知识库的导入耗时、检索耗时和内存。第二版增加取消 Worker/事务、旧索引兼容、单层章节引用与关联分组预算的验收场景。解析和建索引已移入 Worker；IndexedDB 索引游标扫描、打分和候选渲染仍由面板处理，性能提升幅度尚未实测。后续可增加模型 token 估算、全文检索统计排序和语义检索，不在本版隐含启用。
