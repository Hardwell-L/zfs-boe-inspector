# BOE 低版本兼容改造设计

状态：设计与首轮代码实现同步维护。日期：2026-09-22。修订：补充奇瑞 1.0 系列、时代新材 3.7，明确低版本不追求功能对齐，以兼容性、只读性和有限开销为先。

当前首轮代码已实现入口隔离、Vue2 Mixin 生命周期、基础模板/原始数据采集、快照兼容元数据、序列化预算和低版本规则跳过；3.x 的 `boeDesign` 分组与旧版动态状态读取仍按设计保留为后续增量，不在本轮宣称已启用。

## 1. 结论与目标

在现有 `@zfs-boe-inspector/adapter-vue3` 包内增加兼容层，保留统一的安装命令、导入路径和零参数 Mixin。内部识别 Vue 运行时、BOE 源码布局和实际可采集能力，共用现有 Runtime、Collector、Bridge 与扩展面板。

本次目标是以局部改动接入已提供的 BOE 1.0 系列、2.x、3.3、3.7 项目，同时保留 4.2 Vue3 的现有能力。低版本不要求具备高版本全部功能：先保证安装、页面运行、基础字段检查和卸载清理，再按已验证的能力开放增强功能。不能为补齐功能引入高开销遍历、额外业务请求或隐含依赖。

**最高兼容约束：本次改造不得影响高版本现有功能、默认行为和接入方式。低版本方案与此冲突时，应收缩或调整低版本方案，不能以高版本功能降级作为代价。** 此处高版本指当前已支持的 BOE/Vue3 项目，以联投 4.2 作为已核实的回归样本，不据此宣称所有未来版本都已验证。

以下内容是实施设计，不代表已发布的 API 或已通过的兼容性验证。

### 1.1 对外约束

- 安装命令保持 `npm install @zfs-boe-inspector/adapter-vue3`，不新增需要用户单独安装的适配包。
- 导入路径保持 `@zfs-boe-inspector/adapter-vue3/zfs-boe`。
- `createBillTemplateInspectorMixin()` 保持零参数可用，无需指定 BOE 或 Vue 版本。
- 不要求业务项目修改 webpack、Babel、alias 或 `transpileDependencies` 配置。
- 不升级宿主 Vue，不要求 Vue2.6 安装 Composition API 插件。
- Chrome 扩展的安装和打开方式保持不变；使用低版本诊断需要更新到支持本设计的扩展版本。
- 不修改业务项目的 `node_modules`，不使用安装脚本改写宿主文件。

```javascript
import {
  createBillTemplateInspectorMixin,
} from '@zfs-boe-inspector/adapter-vue3/zfs-boe';

export default {
  // 保留当前 extends、components、其他 mixins 和业务逻辑
  mixins: [createBillTemplateInspectorMixin()],
};
```

接入仍需修改实际使用的 `billTemplate`。自动识别版本不等于自动为所有未接入的组件注入 Mixin。

### 1.2 首次实施范围

必须完成统一安装和入口、基础快照、字段原始配置与当前值、具备 DOM 身份的字段定位、诊断降级、生命周期清理，以及 Vue3 回归保护。配置描述、区域定位、差旅原始数据按实际能力提供；全量字段运行态和低版本过程记录不是首次接入的阻塞项。

不包括低版本全部业务算法重写、任意历史目录结构自动搜索、自动修改单据、请求重放、旧浏览器兼容或任意构建工具兼容。浏览器要求继续沿用项目现有的 Chrome/Chromium 114+；Vue2 兼容不意味着支持 IE。

### 1.3 功能分级

| 层级 | 功能 | 低版本默认策略 |
| --- | --- | --- |
| 基础必需 | 注册、最终模板、数据、原始属性、字段值、注销 | 满足组件契约即提供；截断和缺失必须可见 |
| 低成本增强 | 配置分组、已知 DOM 定位、已有差旅数据、静态配置检查 | 来源与语义已确认则启用，否则显示未支持或未采集 |
| 高成本或侵入性增强 | 全量字段运行态、组件子树遍历、方法包装、完整差旅算法诊断 | 低版本默认关闭；按功能单独验证和显式启用，不因版本号自动全开 |

“显式启用”是使用增强功能的可选操作，不改变零参数基础接入，也不要求用户手动选择版本。首次实施可以只显示这些增强功能未支持；不为开关引入一套大型配置系统。

### 1.4 高版本保护要求（实施与发布硬门槛）

- 高版本继续走原有成熟采集与诊断逻辑；统一入口只增加必要的识别和分派，不顺带改写高版本业务语义。
- 原有 Mixin、setup helper、零参数自动配置、显式 options、差旅自动发现与共享注册均保持可用，不要求现有项目改代码或重新开启功能。
- 低版本的 `runtime-only` 回退、规则跳过、过程记录禁用、扫描限制、序列化预算、身份后备和生命周期特殊处理，必须以明确的低版本条件限定，不能修改共享模块的全局默认值。
- 高版本模块加载失败或识别异常时保留可诊断的错误，不能自动切成低版本基础模式并显示“正常连接”。不能仅因兼容元数据缺失或某个数据容器暂时为空，就把原有高版本功能判为不支持。
- 字段描述、动态状态、差旅、校验/计算/关联申请诊断、字段/区域定位、过程记录、导出及 AI 上下文均属于回归范围；不能以界面能打开代替功能无影响。
- 高版本安装和构建不得因低版本探测增加必需依赖、模块缺失 warning 或宿主配置要求；不得重复打包 Vue、引入旧版业务模块或产生明显的运行时性能回退。
- 共用 Runtime、协议、规则、序列化或面板必须改动时，采用可选增量与分支隔离，并验证新扩展读取旧高版本 Adapter、新高版本 Adapter 被已有支持客户端读取的行为。
- 任一高版本回归未通过，或者尚未执行必要验证，均不能宣布“兼容完成”或发布推广。优先撤回造成回归的低版本改动，不要求用户接受高版本降级。

## 3. 当前阻碍与最小改动方向

| 当前实现 | 低版本问题 | 改造方向 |
| --- | --- | --- |
| `zfsBoe.ts` 静态引入 Vue3 API 和新版 BOE 路径 | Vue2.6 缺少 API，旧 BOE 路径不存在 | 由发布包物理入口把 webpack 4 导向 legacy 文件，高版本继续使用原入口 |
| 仅使用 `beforeUnmount` | Vue2 销毁后 Collector 可能残留 | 同时提供 `beforeDestroy`，清理操作保持幂等 |
| peer 限定 Vue3 / BOE 4.2+ | 安装冲突 | 调整经验证的版本范围，BOE 包继续为 optional peer |
| 仅用 `exports` 映射 `./zfs-boe` | webpack 4 不能依赖该映射找到实际文件 | 发布包根目录的物理子路径入口 |
| TypeScript 输出 ES2022 | 旧 webpack 可能无法解析未转译依赖中的新语法 | Adapter 发布产物降级语法，宿主无需转译它 |
| 默认填充缺失差旅数据为空集合 | “采不到”被视为“没有请求／没有结果” | 增加可选采集能力信息，按前置条件执行规则 |
| 区域定位依赖 `${areaCode}.billArea` | 老版区域 DOM 不匹配 | 增加限定在当前单据范围内的旧版定位 |

## 4. 统一入口与自动识别

### 4.1 结构

```text
原有 zfs-boe 导入入口
  → 内部兼容层
      ├─ Vue 实例与生命周期识别
      ├─ BOE 配置来源识别
      └─ 字段、差旅和过程记录能力识别
  → 共用 Collector / Runtime / Bridge
  → 共用面板与规则引擎
```

版本信息用于显示和辅助判断；具体采集逻辑由实际存在的数据、已确认的结构和方法签名决定。Vue2.7 仍按 Vue2 生命周期处理，不因其包含部分 Composition API 而进入 Vue3 分支。

确定运行时属于已支持高版本后，固定使用高版本采集策略，不继续执行旧目录回退或旧版默认限制。配置来源和能力仍按实例记录；策略可以缓存，但不会因为本次快照某个容器为空就切换版本分支。

### 4.2 配置来源识别

内部保留三个已确认的可选描述来源，并增加无需描述模块的基础回退；不新建对外 npm 包：

| 来源 | 配置路径 | 使用前提 |
| --- | --- | --- |
| 新版内嵌核心 | `@zfs/boe/zfs-boe-core/src/config/boeDesign` | 对应模块存在且导出契约有效 |
| 旧版独立核心 | `@zfs/boe-core/src/config/boeDesign` | 对应模块存在且导出契约有效 |
| 旧版本地源码 | `@/components/pages/config/boeDesign` | 项目已有 `@ → src` 别名且文件存在 |
| 仅运行时契约 | 不导入额外配置模块 | 前述描述不可用，但组件有有效模板和数据；奇瑞属于此类 |

按上述顺序探测，并结合 Vue 实例检查是否与支持的组合一致。模块存在但初始化失败、结构不符或版本组合异常时应记录原因，不静默冒充另一个已支持来源。

本地源码路径只承诺已核实的约定，不扫描全项目。允许在现有 options 中增加可选配置覆盖，例如直接传入 `areaConfig`、`fieldConfig`；这类扩展仅用于目录定制项目，不是五个标准样本基础接入的要求。具体参数在实施时与 `BillTemplateCollectorOptions` 对齐，不新增多套同义配置。

配置描述不可用时，仍可读取最终模板和原始属性；分组标签不足应显示降级提示，不阻断基础 Bridge。

不为了奇瑞新增多个文件探测路径，不把 `config/fieldInfo.js` 强行转换为 designer 属性描述。无需精确 BOE 版本或完整描述表也能使用基础功能。描述来源识别和功能开放分开，`standalone-core` 不代表相同差旅算法。

### 4.3 构建入口隔离

为避免 webpack 4/5 同时解析彼此不存在的 BOE 模块，兼容判断放在发布包的入口分派，而不是在一个文件中写可选 `require`：

- `exports['./zfs-boe'].import` 继续指向 `dist/zfsBoe.js`，保留 Vue3/BOE 4.2 原入口和原有静态依赖。
- 包根目录增加物理 `zfs-boe.js`，webpack 4 不读取 `exports` 时解析到 `dist/legacy/legacyZfsBoe.js`。
- legacy 入口只依赖共享 Collector、Runtime 和 Vue2 生命周期，不导入 Vue3 API、`@zfs/boe` 或新版 `fieldDynamicConfig`。
- modern 入口保留已验证的 `areaConfig`、`fieldConfig` 和动态配置导入；旧版本不安装这些依赖也不会被该入口解析。
- 两个入口共用安装包名、子路径字符串和 Mixin 名称，版本由构建器解析能力和实际 Vue 生命周期共同决定；Vue2 入口误被 Vue3 运行时加载时给出明确错误。

该边界避免了统一入口因缺失候选模块产生的 webpack warning，也避免把旧业务模块打入高版本 bundle。仍需在真实 webpack 4/5 tarball 样本中验证入口解析和 external Vue；未完成该验证前不能宣称发布级兼容。

### 4.4 Vue API 与生命周期

- 通用 Mixin 本身不依赖 `getCurrentInstance`；从 mounted 的真实组件实例识别 Vue2 / Vue3。
- Vue3 从当前 app 读取版本；Vue2 从实例关联的 Vue 基类等已验证入口读取版本，不能假设每个子组件构造函数都有 `version`。
- 读取不到精确版本时允许未知，不阻断采集；不能用 node_modules 的版本替代 CDN 实际运行版本。
- 同时提供 `beforeDestroy` 和 `beforeUnmount`，共用幂等注销逻辑，继续复用注册池的引用计数。
- 检查 keep-alive 场景：缓存中的非活动单据不参与当前选择和可选过程记录；deactivated 释放或暂停注册，activated 按幂等逻辑恢复，不能假设每次离开都会触发 destroy。
- 保留现有 Vue3 `useBillTemplateInspector`、`useTravelInspector` 导出和行为；Vue2 物理入口不导出可误用的 setup 运行时，避免 Vue2.6 在导入阶段解析不存在的具名导出。
- Vue2.6 本次仅承诺 Mixin 接入；误用 setup helper 应得到明确的能力不支持信息，不要求安装插件。

## 5. 采集与诊断行为

### 5.1 基础配置和元数据

继续采集组件最终的 `template` 和 `data`，不重复请求模板接口，不调用 `dataFormat`。配置描述按实际宿主来源读取并沿用现有净化逻辑，不复制整套 designer。

有对应包时记录真实包版本；奇瑞、绝味无 `@zfs/boe` 时不伪造该包的版本。保留 `projectCode` 默认来自页面 host 的行为。项目 `package.json.version` 与 BOE 包版本属于不同含义，不互相代替。

基础采集还需兼容奇瑞的模板暂时为 null，以及 `billInfo.boeHeaderId`、`billInfo.boeNo` 身份来源。模板尚未就绪时不输出“字段缺失”问题，不改读 `allTemplate` 冒充当前模板。身份优先使用已确认的业务 ID；尚无 ID 的多个新建单据使用组件实例级稳定后备标识，不全部合并到 `UNKNOWN:active`。现有业务 ID 的优先级不变，身份变化时同步清理选择和过程记录状态，避免跨单据缓存复用。

### 5.2 字段动态状态

Vue3 保留已确认的现有采集分支。Vue2 基础模式默认不执行全量运行态采集，显示当前字段值与静态配置，并明确“运行态未采集”。可选运行态读取器仅在对应能力完成只读审计后启用，输入为当前 `billTemplate`，输出沿用 `FieldRuntimeState`；不为提供此功能新增全局监听和常驻深度 watch。

增强模式优先读取实际已挂载字段组件的已生效值，例如项目覆盖后的 `disabledFlag`。按需只检查当前选择目标，定位不到则保持未知；确有需要时才在当前单据子树内作有界遍历，按 `areaCode`、`rowIndex`、字段编码匹配，不遍历整页实例。全量增强每次显式请求最多遍历一次，设置节点、深度和时间预算，达到任一上限即返回部分结果，不阻塞基础快照。

状态处理约束：

- 不重放 `NANDgate`、校验、计算、字段销毁或数据源方法。
- 不把 `isEdit` 静态配置等同于最终可编辑状态；审批模式、行控制和本地覆盖都可能改变结果。
- `v-if` 未挂载、折叠、分页和虚拟列表造成的组件缺失不能直接判为隐藏。
- 只在字段已挂载且证据能唯一对应时读取状态；未知属性不填 `false`。
- getter 异常或单字段采集失败只影响该字段，记录原因并继续其他字段。
- 可见性、可编辑性、必填性分别判断是否有证据，不要求三项同时存在。

规则层需区分“静态配置”与“最终运行态”。对于明确标记为低版本且运行态不完整的字段，不能再无条件回退静态值并输出“当前必填但隐藏”等确定性问题。字段值、原始配置和依赖分析仍可展示；缺少前置证据的状态规则返回 `skipped` 或诊断模型的 `unverified`。

基础模式继续遵守当前架构“避免组件树遍历”的约束。受限遍历仅属于可选增强，不是低版本兼容的必须改动。

### 5.3 差旅数据与规则

继续从已接入 `billTemplate` 的父级链发现已知差旅宿主，复用现有共享注册池。父链名称或结构经过定制时继续使用已有 `resolveTravelComponent`。

宿主名称匹配后仍需检查数据契约；奇瑞虽叫 `TRAVEL_BOE`，不能因此注册一个全部为空的新版 Travel Snapshot 再让规则补出 passed。缺少可确认的差旅模型时，不注册专用差旅 Collector，单据中的 travel/stay/subsidy 等区域仍可作为普通字段查看。

| 数据或规则 | 老版处理 |
| --- | --- |
| 日历、行程、人员和原始标准结果 | 存在则采集；保留实际结构 |
| 按日期请求记录 | 缺少对应记录容器时标记未采集，不构造请求记录 |
| 按地点保存的标准缓存 | 标记缓存方式为地点；保留原键，不伪造成日期＋地点 |
| 日期缺失、日期重复等基础检查 | 有相应日历或行程证据时执行 |
| 请求缺失、按日期结果缺失、日期关联和日期＋地点命中 | 前置能力不足时逐规则 `skipped` |
| 类型、汇总、去重和控制等级 | 仅对已确认具有对应语义的证据执行，否则跳过 |

中车电机 3.3 样本取地点末段作为缓存键，绝味 2.x 样本直接使用地点值；时代新材 3.7 的上游 `getStandardAmount` 按是否传入日期写入两种键，可能形成混合缓存。不能写死“Vue2＝地点缓存”，也不能写死“独立核心＝同一种缓存”。首次实施保留原始键和值；混合或不明语义的键策略标记为 `mixed` / `unknown`，依赖全局统一键规则的诊断跳过。即使有日期缓存，缺少请求历史的相关规则仍须跳过。

不调用 `getStandardAmount`、`checkStandard`、`beforeSubmit`，不为填补快照而发起业务请求。缓存和请求容器已经存在但当前为空，与该版本根本不提供容器是两种状态。

### 5.4 页面定位

字段继续优先使用已有 DOM ID 和 `labelCode` 回查。区域定位保留新版 `${areaCode}.billArea`，旧版使用已确认的区域标题 ID、`.bill-area` 容器以及必要的区域组件引用建立映射。

所有查询限定在当前实例 `$el` 内；选择器和“定位”共用同一套区域解析，避免一边能选另一边不能定位。隐藏标题区域、重复 ID、多单据和折叠区域必须纳入验收；无法唯一定位时返回未找到，不跨单据匹配。

### 5.5 过程记录和其他诊断

Vue3 保留现有可撤销方法观察机制。低版本基础模式不安装方法包装器；只有签名、返回值和销毁恢复已经单独验证的方法才允许用户主动开始记录。方法名存在只证明入口存在，不证明参数契约相同；例如旧版 `reComputed` 的参数不能直接套用新版字段触发参数解析。首次实施允许低版本过程记录整体显示未支持，不为追求覆盖率重写事件系统。

面板的过程记录入口应根据当前单据能力禁用并说明原因；Adapter 的 `startTrace` 同时拒绝未支持实例，不能只隐藏按钮。当前 Bridge 的全局 capabilities 表示接口存在，不足以表达各实例是否可以记录，需结合快照中的可选能力信息判断。

基础校验、计算、动态和关联申请配置解析继续复用；仅处理样本证实的结构差异。缺少运行态时保持未验证，不通过主动执行函数补全结果。

### 5.6 性能设计与有限资源

现有代码中，`runtime.getFieldDetail`、`getAreaDetail`、`startPicker` 会调用 `getSnapshot`；`serialize.ts` 默认全局节点数和字符串限制为 Infinity。直接把老版组件遍历接到每次快照上，会放大字段点击和重复读取的成本，因此本次不采用这种默认行为。

| 环节 | 设计要求 |
| --- | --- |
| 页面加载与未使用时 | mounted 仅注册并取得必要元信息；不立刻深复制整张单据，不启动全量快照轮询、组件扫描或深度 watch |
| 来源识别 | 固定数量候选；同一页面环境只解析一次，失败结果也缓存；不按历史版本增加无穷路径 |
| 快照 | 用户刷新或已有明确请求时采集；同一次操作共享结果，避免同时读取字段详情、区域详情、规则时重复序列化 |
| 状态新鲜度 | 不按对象引用永久缓存数据，Vue2 可能原地修改；复用仅限同次操作，显式刷新重新读取，并保留 capturedAt |
| 描述缓存 | 仅缓存净化后的描述与来源，不缓存 Vue 实例到全局强引用列表，不重复转换同一描述表 |
| 组件增强 | 默认不扫描；开启后仅当前单据，显式全量请求最多遍历一次，不对每个字段重新遍历整棵树 |
| 页面选择 | 仅用户开启期间监听；mousemove 最多每动画帧处理一次，重复目标不重复测量；悬停不采集快照 |
| 父链发现 | 延续当前最多 5 层父链限制，不扩展为全页差旅搜索 |
| 规则 | 使用一次构建的字段/区域索引；截断或能力不足先判定跳过，不重跑宿主逻辑 |
| 内存与清理 | 最新快照按活动实例受限持有，不保留无限历史；注销时释放实例、DOM 引用、计时器、监听和可选观察器 |

低版本采集建议采用以下初始预算。它们是待测量校准的实现参数，不是已达到的性能结论，也不是硬实时保证：

| 项目 | 初始预算建议 | 超限处理 |
| --- | --- | --- |
| 单次快照序列化 | 所有 Collector 合计最多 20,000 个节点，深度最多 20；每个集合最多 1,000 项 | 返回结构有效的部分结果，记录截断位置及计数 |
| 文本与输出 | 单字符串最多 8,192 字符，累计字符串与键最多 1 Mi 字符；最终 JSON 传输目标上限 2 MiB（UTF-8） | 先在遍历阶段限制，再检查输出；无法安全缩减则返回采集失败原因，不能交付破损 JSON |
| 可选组件扫描 | 最多 1,000 个节点、深度 20、软时间预算 8 ms，任一达到就停止 | 返回 partial，不自动循环补扫或后台重试 |
| 重复警告 | 同类原因按实例和采集批次合并 | 保留位置和数量，不为每个未挂载字段生成大量相同文本 |

实施时优先把已有序列化预算参数接入低版本分支，并给多个 Collector 分配总预算，不能让每个 Collector 分别消耗整份上限。根 `template` 仍应保持数组等协议形状，截断标记不能被当作普通字段参与诊断。

时间预算在读取 getter 前后与遍历节点间检查，无法中断单个不返回或耗时的同步 getter，也无法用 Promise/定时器消除同步 JSON 序列化的阻塞。疑似昂贵或有副作用的 computed 不读取；优先拿已有 data/props。遇到上限或异常停止增强，不能用重试拖慢宿主。

快照被截断时按受影响范围标记“不完整”，依赖完整字段图、全部日期或汇总的规则跳过；不能从截断数据推断字段不存在、没有请求、没有循环或汇总正确。导出、面板和 AI 必须同时保留限制信息。本次不得将更严格的低版本预算、截断和规则降级默认应用于高版本；高版本预算调整属于独立需求，不纳入本次兼容改造。

## 6. 最小协议增量与新旧版本组合

为了让面板和规则区分“没有数据”与“不支持采集”，建议新增一个可选的 Snapshot 兼容信息对象。下列为拟议字段，最终定义集中放在 `shared-types`，不在各模块自建不同格式：

| 拟议字段 | 含义 |
| --- | --- |
| `compatibility.profile` | `embedded-core`、`standalone-core`、`local-source`、`runtime-only` 或 `unknown`；表示来源而非精确版本；仅运行时回退不冒充已确认源码来源 |
| `compatibility.fieldRuntime` | `complete`、`partial`、`unavailable`；概述本次采集完整性，具体属性仍以字段证据为准 |
| `compatibility.trace` | `available` / `unavailable`；当前实例是否允许过程记录，不取代已有 Bridge 接口能力声明 |
| `compatibility.travelRequestHistory` | `available` / `unavailable`；区分空容器与缺少容器 |
| `compatibility.travelCacheMode` | `date-site` / `site` / `mixed` / `unknown`；结合已确认实现与本次实际结构，不只看 Vue 版本或 profile |
| `compatibility.collection` | 本次 `complete` / `partial` / `unavailable` 状态与受影响证据路径、原因；表达模板未就绪、预算截断和读取失败，供规则判断前置条件 |

错误和降级原因继续写入现有 `warnings`；结构化状态供程序判断，warnings 用于说明，不能靠匹配中文提示控制规则。兼容信息按单据快照生成，不能因 Runtime 单例而串用另一实例的能力。`complete` 表示预算内的本次基础采集完整，不表示已提供全部高版本功能。

优先作为 schema 1 的向后可读增量，不新增 Bridge 方法。实施前应核对校验器、Collector 合并、导出、规则以及 AI 上下文的完整传递；如果无法保持高版本原有协议语义，应修订低版本协议增量方案，不能通过强制高版本升级协议或客户端来满足本次兼容需求。

| 组合 | 约定 |
| --- | --- |
| 新扩展＋旧 Vue3 Adapter | 没有兼容字段时保持现有行为 |
| 新扩展＋新 Vue3 Adapter | 保持原功能，使用真实能力信息 |
| 原有支持客户端＋新高版本 Adapter | 既有字段和接口语义保持可读可用，不能要求高版本用户为兼容低版本而更换接入代码 |
| 新扩展＋新低版本 Adapter | 执行低版本能力判断与降级规则 |
| 旧扩展＋新低版本 Adapter | 不属于支持组合；旧规则忽略新字段，仍可能误报 |

发布顺序为先支持能力字段的扩展，再推广低版本 Adapter 接入。安装方式不变不等于旧扩展无需更新；不能宣称新增字段能自动阻止旧扩展执行旧规则。

## 7. 发布产物与依赖约束

1. 保留包名和原有 `exports`，增加包根目录实际 `zfs-boe.js` 转发入口及必要声明，使 webpack 4 不依赖 `exports` 解析子路径。实际入口也必须进入 `files` 和 npm tarball。
2. modern/legacy 分别编译，legacy 目标为 ES2018；不在统一入口放置跨版本可选 `require`，避免高版本新增缺失模块 warning。
3. 对 `shared-types` 的实际运行时产物一并检查。降级语法不引入全局 polyfill，现代浏览器 API 仍受现有 Chrome 版本约束。
4. Vue peer 建议覆盖 `>=2.6.0 <3 || >=3.4.0 <4`，不意外扩大到未经评估的 Vue3.0～3.3。版本范围是安装约束，不等于该范围全部发行版已验收。
5. `@zfs/boe` peer 放宽到所需系列并继续 optional；独立 `@zfs/boe-core` 如声明 peer，也必须 optional。奇瑞、绝味无这些包时不能自动安装它们；奇瑞没有任何 `@zfs` 包也可使用基础模式。
6. Adapter 与 `shared-types` 当前 `node >=22.12.0` 声明需要与宿主消费要求分离。优先移除没有实际运行时依据的消费端限制；若必须声明下限，依据验证结果确定。仓库构建工具的 Node 要求不变。
7. 发布包不增加 postinstall；不要求 `--force`、`--legacy-peer-deps`，不夹带 Vue 运行时副本。
8. 优先沿用 TypeScript 和已有脚本完成转译、复制入口与打包，不先引入新的 bundler 或 `vue-demi`。

## 9. 分步实施与检查点

### 第一阶段：统一入口可消费性

先完成物理入口、兼容加载、依赖范围和发布语法；使用实际 tarball 验证五个样本工具链对同一 import 的处理。明确记录可选依赖 warning、新增依赖图与体积、production external Vue 和旧 Node 消费限制。

通过条件：五个样本无需改构建配置即可解析入口，Vue2.6 不因 Vue3 API 导入失败，缺失其他布局的模块不形成必需依赖，奇瑞无配置描述也可进入基础模式。若不通过，停止扩大实现范围并修订入口方案。

### 第二阶段：生命周期和基础采集

接入实际 billTemplate，验证可用的配置描述、最终模板、数据、身份、空态和注销；保留 Vue3 Mixin 与 setup 两条路径。单独核对哪些单据真正使用被修改的组件。

中车电机的 `TRAVEL_BOE`、`NEW_TRAVEL_BOE` 已引用本地 billTemplate；`MULTI_TRAVEL_BOE` 的本地 wrapper 没有注册它，需要沿实际组件链确认并在必要处补注册，不能声称一个文件天然覆盖所有单据。

### 第三阶段：定位、预算与诊断降级

补可确认的旧区域定位、基础采集预算、能力元数据及防误报规则。奇瑞不补做 designer 和新版差旅模型，所有低版本不以全量字段运行态或过程记录作为通过条件。能力缺失与截断提示、导出同时完成，避免仅做到“已连接”就宣布兼容。

### 第四阶段：版本回归与发布说明

完成下述验收后再填写正式支持版本范围。先更新扩展，再提供低版本接入说明；发布和外部项目修改按届时授权执行。

低版本基础兼容与高版本无回归两项验收均通过后，才能完成本次实施。只有后续需求或样本证据确有必要时，再单独实现有界字段扫描和旧版过程记录，不为了补齐高版本菜单扩大工作范围。

## 10. 验收清单

以下是未来实施的验收要求，本次文档编写没有执行这些构建、测试或页面操作。当前技能默认只允许修改后 lint；实施时若仍适用该限制，构建、测试和浏览器验收需有明确授权。未执行前只能报告静态检查结论，不能标记兼容验收通过。

| 类别 | 场景 | 通过标准 |
| --- | --- | --- |
| 安装 | 四个 Vue2 样本与现有 Vue3 样本 | 不需要强制安装，不引入额外 Vue 或不存在的 BOE 包 |
| tarball | webpack 4/5 消费发布包 | 相同 import 可解析，物理入口和两套编译产物存在；记录全部新增 warning |
| Vue | Vue2.6、Vue2.7、Vue3 | Mixin 均可注册；Vue3 setup 保持可用；Vue2.6 import 不触发缺失 API |
| 生产模式 | Vue external 到 CDN | 按页面实际运行时工作，不依赖仅开发环境存在的导出 |
| 生命周期 | 进入、离开、重复进入单据、keep-alive、多个新建单据 | 注册与释放匹配；缓存页恢复不重复注册，非活动实例不参与当前采集；无业务 ID 的实例不合并 |
| 基础采集 | 普通单据、差旅单据、奇瑞模板暂时为 null | 最终模板、数据和可用描述与页面一致；未就绪不误报，无描述不阻断 |
| 覆盖 | 各单据实际组件链 | 确认接入点覆盖，未覆盖的单据明确列出 |
| 动态状态 | 默认模式以及可选增强启用后的审批、折叠、分页等场景 | 默认不扫描、不伪造状态；若实现增强则尊重实际状态，未挂载不推断隐藏 |
| 定位 | 普通字段、table-search、明细、隐藏标题区域、多单据 | 选择和定位一致；仅作用于当前实例，不能唯一定位则失败 |
| 差旅 | 地点缓存、3.7 混合缓存、奇瑞无新版模型、存在但为空的请求容器 | 不虚构日期请求；无能力不制造全 passed；缺证据规则明确 skipped |
| 过程记录 | 基础模式和另行验证的可选增强 | 默认无方法包装；未实现可以标记未支持；已实现的增强停止后恢复原方法 |
| 只读边界 | 刷新快照、选择、诊断 | 不增加业务 Network 请求，不修改单据、缓存和配置 |
| 协议 | 新扩展读取旧快照及新旧 Adapter | 缺少新字段时正确回退；未知与空值区分；导出和 AI 保留限制 |
| 高版本完整回归 | 字段描述/运行态、差旅、校验/计算/关联申请、定位、过程记录、导出、AI | 与改造前相同输入和操作的业务结果一致；忽略时间戳等非业务差异，不接受功能减少或额外规则跳过 |
| 高版本接入回归 | 原有零参数 Mixin、setup helper、显式 options、自动差旅及销毁恢复 | 不改业务接入代码和默认参数，原有行为保持一致 |
| 高版本构建与性能 | 同一依赖锁定环境、同一页面/单据，改造前后对照 | 无新增模块缺失 warning、必需依赖或宿主配置；记录耗时、体积与内存对比，无明显性能回退 |
| 分支隔离 | 高版本缺少新增兼容元数据、暂时无差旅数据、配置加载异常 | 不误进低版本模式、不触发低版本预算和功能禁用；真实错误不被静默回退掩盖 |
| 性能与体积 | 相同样本接入前后，描述可用／不可用 | 记录产物增量、模块图、首次挂载开销、刷新耗时与输出大小；不得打包无关业务或 designer UI 全集 |
| 空闲开销 | 页面已接入但不打开 Inspector | 不周期性扫描、全量采集或包装业务方法 |
| 大单据 | 构造含 1,000 行明细、长字符串与超过节点预算的数据 | 及时截断且形状有效，不按字段数重复扫描；受影响规则跳过，显式刷新不读旧数据 |
| 资源回收 | 同一路由进入/离开 20 次 | Inspector 注册数回落，DOM 引用与监听无持续累积；记录内存趋势而非承诺固定字节数 |

验证优先覆盖入口解析、生命周期、错误规则结果和状态语义等契约风险；不为简单转发文件增加镜像式测试。使用隔离消费环境或授权的项目副本，避免验证时修改业务项目 lockfile 或依赖安装目录。

在实施前保留高版本基线：锁定同一宿主依赖，保存代表性快照、规则结果、接入方式和操作路径；共享模块改动以该基线作对照。性能比较需记录环境并重复测量以排除偶然波动，不将单次耗时变快或测试通过等同于绝对无影响。任何未解释的功能差异或明显性能退化均阻断发布。

## 11. 风险与待确认事项

| 风险 | 处理与边界 |
| --- | --- |
| 入口解析与产物边界 | 作为第一阶段明确结果；需用真实 tarball 核验 webpack 4/5 入口和 external Vue，不全局屏蔽 warning |
| 包的 ESM/CJS 混合产物或 Vue external 行为不符预期 | 必须验证实际 tarball 的开发和生产消费，不能只验证源码 |
| 本地目录定制 | 默认支持已确认路径；定制项目可显式提供配置，不能保证任意布局零参数 |
| 读取组件 getter 有副作用 | 逐个核实读取项，只读必要字段；无法确认的项目覆盖保持未知 |
| 大单据与重复快照 | 合并同次读取、全局采集预算、截断可见；不为全功能一致默认扫描 |
| Vue2 原地更新与缓存陈旧 | 不使用对象引用作为永久快照缓存有效条件，显式刷新重新读取 |
| 3.7 混合缓存 | 来源布局不能决定键模式；保留原结构，跳过不满足前置条件的规则 |
| 低版本业务差异 | 按能力降级，不复制计算算法，不承诺所有功能完全等价 |
| 旧扩展忽略兼容信息 | 明确最低配套扩展版本并先升级扩展，不能只更新 Adapter |
| 精确 BOE 版本不可得 | 记录来源与可用元数据，不把项目版本推断成 BOE 包版本 |
| 样本之外的 4.2 以下项目 | 依据布局和契约扩展样本验证，不以数字范围替代验证 |

第一版不需要用户为标准样本选择版本。必须验证统一入口的构建产物可消费性、warning 对宿主流水线的影响、基础采集的有限开销与资源回收。旧组件深度运行态读取只在实现该增强时验收，不作为基础兼容的前提。
