## 1. 目标、范围与现状

围绕用户提出的六项需求，让主要操作收敛为“选择范围 → 输入问题 → 发送 → 阅读回答 → 切换会话”。保留只读分析、证据引用、脱敏、请求体积限制和模型手动配置能力。截图标注作为位置与交互意图参考，不复制红框或阴影。

本文第 1—8 节记录设计与验收标准，具体实施与检查结果在第 10 节单独记录。实施范围为扩展面板及必要的扩展内部 Bridge 上下文识别，不修改 Adapter/Snapshot/Trace 公共协议，不新增 UI 依赖。

| 用户需求 | 回退后的代码现状 | 目标与验收编号 |
| --- | --- | --- |
| 全插件时间使用当前用户时区，只显示年月日时分 | `AiPanel.vue`、`TracePanel.vue` 直接显示 ISO 字符串 | 展示层统一格式，原始数据不变；T1—T2 |
| AI 布局简单、回答方便阅读 | 标题、三页签、快照、提示、摘要、输入分别占高度 | 合并顶部信息、扩大正文、缩减重复操作；L1—L2 |

## 2. 页面设计

### 2.1 单层导航

取消“对话分析”这个总页签，会话直接出现在 AI 顶部，与范围、模型、问答历史三个功能入口平级：

```text
AI 分析                       模型 deepseek… · 范围 3 项 · 采集 2026-09-17 17:16
[金额计算 ×] [必填状态 ×] [＋]                  [分析范围与证据] [模型设置]
───────────────────────────────────────────────────────────────────────

  你 · 2026-09-17 17:18
  为什么这个字段没有按预期计算？

  AI
  回答正文与证据引用……
  [复制回答] [查看依据]                           主阅读区，独立滚动

───────────────────────────────────────────────────────────────────────
  描述问题或继续追问……                           输入区默认两行
  查看发送内容                                  [发送]
```

- 会话标签占剩余宽度，超出后横向滚动；功能入口单独保留空间，不被标签挤出视口。
- 默认“新会话 N”，未手动命名时第一次有效发送使用问题前 16 个字符作标题，超长省略。提供重命名按钮，也支持双击标题或 F2；Enter/失焦保存、Escape 取消，忽略输入法组合输入。名称去除首尾空格，空名称不覆盖原名称，最多 60 字符；手动名称不会被首个问题覆盖。
- “＋”每次创建独立的空范围、空草稿会话，允许连续新增空会话，不再复用当前空会话。仍需已连接单据且不处于请求/点选锁定状态；尚未产生问答的空会话仅保留于当前面板。
- 功能页不另建会话；进入范围页时显示“当前会话：金额计算”，编辑最近激活会话。返回时仍回到该会话。
- 生成中的会话标签显示“生成中”；允许切到其他会话阅读和填写草稿。
- 关闭无内容会话直接完成；有手动名称、草稿、范围、附件或回答的会话提供一次“撤销关闭”，保留最近一个已关闭会话至下次关闭或面板销毁。生成中的会话先停止，再关闭。
- 关闭当前会话后选左侧邻居；没有左邻居则选右侧；最后一个关闭后创建空会话。范围页、抽屉的归属同步更新。
- 标签支持键盘左右键、Home/End；会话关闭按钮有独立可访问名称。功能入口可通过 Tab 到达。

### 2.2 阅读与输入

- 标题右侧只放模型、范围数量、快照采集时间；模型和范围可点击。移除独立快照栏、摘要按钮行和常驻内部状态通知。
- 请求字节数、自动关联证据、历史截断数量和采集完整性移到范围页或发送内容中。
- 正文白底，建议 14px、行高 1.75，阅读列最大 1120px，左右留 16—24px；消息全文展开，不增加整篇回答的小滚动框。
- 用户问题轻底色，AI 正文减少边框。正文默认只保留复制、查看依据；输出截断才出现“继续生成”，失败才出现对应错误说明。
- 回答旁显示本轮发送时间；模型、范围、快照时间置于“查看依据”。不使用快照时间冒充消息时间。
- 空会话引导文字可点击并跳转当前会话的“分析范围与证据”，支持键盘聚焦与激活；显示三条快捷问题；有回答后隐藏快捷问题，移除大图标和大面积欢迎占位。
- 输入框默认两行，可向上扩展至工作区高度的 25%；提供收起/展开入口，收起后仍保留一行继续提问入口。
- 输入区只保留一个主按钮，按状态显示“发送 / 取消准备 / 停止生成”。准备阶段可在按钮旁显示“准备中…”。新建会话统一放在顶部“＋”。
- Ctrl/Cmd + Enter 发送，Enter 换行；输入法组合输入期间不触发发送。未选范围、缺少模型配置等阻塞提示放在输入框附近。
- 用户靠近底部时跟随流式回答，向上阅读后停止跟随并显示“回到最新”；分别保存各会话滚动位置，返回时恢复。
- 发送草稿提交成功进入模型请求后清空；准备失败保留原稿。模型失败时本轮问题和部分回答保留，可显式恢复问题到输入框再发送，不自动重试。

### 2.3 范围页、返回入口与窄屏

- 范围页保留现有字段搜索、行选择、已选项、分组选择和默认脱敏行为；标题显示所编辑会话。
- 范围页保留次要“刷新数据”按钮，用于查看最新字段值；对话顶部不再放刷新按钮。
- 工作区宽度不小于 700px：返回按钮位于内容视口右侧中部，距右边 16px；外壳 `position: relative`，按钮在滚动区之外独立定位。内容预留约 120px，避免遮挡复选框和滚动条。
- 小于 700px：返回按钮改到范围页顶部右侧的常驻工具条，并为工具条占位。模型设置页复用该入口。
- 响应式判断采用工作区容器宽度，而非只看浏览器窗口；小于 480px 时功能入口缩为“范围与证据 / 模型”，采集时间移入详情。
- 低于 600px 高度隐藏标题说明、空会话快捷卡片等辅助内容；确保输入与发送可达。正常 700px 及以上高度，标题导航和默认输入区合计目标不超过 240px。

## 3. 全插件时间展示

“当前用户的时间”指用户浏览器/系统本地时区中的真实事件时刻。历史事件不替换成当前时钟，不写死北京时间，不手动加减固定小时数。

- 新增共享展示工具 `formatLocalDateTime`，用 `Intl.DateTimeFormat` 与 `formatToParts` 输出 `YYYY-MM-DD HH:mm`，明确公历、`numberingSystem: 'latn'` 和 `hourCycle: 'h23'`，使用运行环境默认时区。
- 截图 `2026-09-17T09:16:58.697Z` 在 `Asia/Shanghai` 显示 `2026-09-17 17:16`。跨日、夏令时由运行环境处理。
- 已知时间戳接受带 `Z` 或时区偏移的完整日期时间；缺失、无效或缺少时区信息时显示 `—`，不猜测偏移。纯业务日期走独立展示路径。
- 统一覆盖 AI 采集/发送时间、预览与依据中的已知时间字段、过程开始/结束/事件时间、插件可读报告中的已知时间字段。只格式化有语义依据的字段，不递归猜测任意字符串。
- `2026-09-17` 这类差旅或费用业务日期保持年月日，不平移、不补 `00:00`。同一分钟的多个事件用列表序号与原有顺序区分。
- 原始 JSON、请求体、快照导出和诊断协议保留原始时间与精度，并标记“原始数据”。采集端 `toISOString()` 保持不变。

## 4. 一次发送与可读证据

### 4.1 发送生命周期

发送流程是一个原子操作，界面不再要求刷新、预览、确认三步。以下顺序属于后续实现约束：

1. 同步取得全局分析请求占用权，记录 `requestId + sessionId`；复制问题、范围、证据偏好、过程附件和完整模型配置。关闭预览，当前发送会话的分析条件暂时锁定。
2. 按会话绑定的页面/单据读取快照并运行本地诊断。刷新接口直接返回结果，不等待共享 props 的 watcher 完成。
3. 检查请求仍有效、所属页面/单据未变、范围仍存在；按锁定参数组装并脱敏，核对上下文和历史预算，再检查完整请求不超过 150,000 字节。
4. 冻结本轮请求、证据、模型、发送时间与采集时间，创建所属会话的回答记录；调用模型一次，后续文本和结果只更新这条记录。
5. 成功、失败或取消后释放该请求的占用权。迟到回调需匹配请求标识，不能覆盖新请求或另一会话状态。

准备阶段取消会使请求标识失效；即使底层快照读取不能中断，返回后也不能继续调用模型。生成阶段通过当前请求的 AbortController 停止，保留已收到文本。组件/面板销毁同时取消准备与生成。

失败策略：刷新失败不使用旧快照继续发送；范围失效或超限显示原因和“调整范围”入口；模型失败只显示局部错误，不自动重试。单击、连击与快捷键同时触发也只能取得一次占用权。

“继续生成”沿用该回答的冻结证据和历史消息，不刷新证据；仍受全局请求占用、当前单据匹配与模型配置一致性检查。服务或模型已变化时引导重新提问，不静默切换服务续写旧回答。

### 4.2 可选的“查看发送内容”

输入区保留一个次要入口。宽屏打开工作区右侧抽屉，建议宽 480px、最大不超过工作区；窄屏使用工作区内全宽面板。提供常驻关闭按钮和 Escape 关闭，关闭后恢复焦点与阅读位置。

| 内容 | 默认展示方式 |
| --- | --- |
| 问题、模型、范围、采集时间、请求大小 | 简短摘要，注明本次携带/省略的历史轮数 |
| 字段证据 | 区域、字段、行、当前值、显示值、显示/编辑/必填状态的表格 |
| 背景与配置 | 属性列表；对象按属性树、数组按列表逐层展开 |
| 诊断 | 诊断结果、关联证据、缺失信息；保留原结论，不凭空生成解释 |
| 过程 | 过程发生时间、方法、状态、输入输出，以及过程所属单据 |
| 技术详情 | 默认折叠的原始脱敏证据/请求 JSON，可复制；不含认证请求头或 Key |

必须区分未采集、缺失、截断、空字符串、null、0 和 false。对象不能只显示 `[对象]`，数组不能只剩数量；长内容可以折叠，但应能展开核对完整的已采集内容。

预览读取与请求相同的 `sentEvidence` 脱敏结果，遵循已有逐项“保留原值”选择，凭据始终移除；不直接显示未经处理的原始快照。问题、标题与结构化值同样经过对应脱敏流程。

发送前标注“当前快照内容，发送时自动更新”；它不是下一次发送内容的承诺。回答中的“查看依据”读取冻结版本，标注“本次实际发送”，包含实际问题、证据和请求记录。引用 `[E1]` 只解析到所属回答，不读当前会话最新证据。

## 5. 多会话状态与入口设计

### 5.1 状态归属

新增面板实例级 `useAiWorkspace.ts`（拟定名称），在 `App` setup 中创建并传给工作区；不使用跨窗口单例。让存储脱离快照是否存在，AI 工作区外壳在断连时仍可显示历史。所有范围/会话命令通过该状态入口处理，取消父子各维护一份范围后靠 watcher 回写的结构。

| 层级 | 必须拥有的数据 |
| --- | --- |
| 工作区 | 会话列表、最近激活会话、当前功能页、全局模型配置、测试状态、唯一活动请求、一次撤销关闭记录 |
| 会话 | ID/标题/创建时间、页面与单据绑定、草稿、范围、证据偏好、DTO 选项、过程副本、最近快照与诊断、回答、上下文依据、脱敏别名、追问锚点、局部错误/提示、滚动位置、输入区展开状态 |
| 单次回答 | 回答 ID、上下文版本、发送时间、快照采集时间、问题与正文、状态、实际模型/服务、冻结证据及定位信息、实际请求记录 |
| 活动请求 | requestId/sessionId、准备/生成阶段、取消状态、controller、点击时的完整配置与分析条件；Key 仅在请求内存使用，不放入回答或证据 |

切换会话只切换视图，不重建证据、不清空草稿、不触发快照刷新。生成 A 时可编辑 B 的草稿；首版将范围变更、页面点选、外部追加和模型修改统一锁定至请求结束，简化跨页面异步边界。B 的发送按钮显示“另一会话正在生成”。切换阅读和保存草稿不走全局 `aiBusy` 的范围更新拦截。

范围、证据勾选和 DTO 选项的改变使该会话下次发送启用新上下文。快照忽略顶层 `capturedAt` 后的内容变化沿用现有隔离原则；只更新时间不打断追问。全局 Base URL/模型变化时，为所有会话标记条件变化，并在下一次发送再次比对，不能只重置当前会话。上下文变化后保留旧回答，在下一轮前显示一次“分析条件已更新”。

历史沿用最近两轮、16,000 字节预算，只取同会话、同上下文的完成回答。脱敏器按会话保持稳定；切换会话不重置别名。证据偏好用现有 `path + kind + selection` 身份关联；“保留原值”仅在对应值未变化时沿用，刷新值变化后恢复默认脱敏。

### 5.2 单据绑定与生命周期

- 单据身份至少包括 `projectCode + environment + instanceId`，还需绑定扩展所连接的浏览器 tab/frame 和页面生命周期。相同实例字符串不代表不同页面属于同一会话。
- 当前 `collector.ts::deriveInstanceId` 在无单据 ID 时回退为 `类型:active`，不能据此保证草稿单据唯一。实施时需核对 Bridge 的页面身份能力；无法确认身份连续时保留旧会话只读，并要求新建会话，不猜测旧会话可继续操作。
- 现有 Bridge 内部有 tab/frame 选择信息，但没有供 AI 使用的完整生命周期契约。可以在扩展内部增加目标上下文标识与变化通知；发送前后都核对目标，不扩大到公共协议改造。
- 切换到其他单据或断连时，旧会话仍可阅读，禁止发送、刷新、追加范围和页面定位。返回已确认同一页面/单据后才恢复操作。

- 保存和清除 Key 的提示也局部展示；测试/保存不修改聊天错误。分析准备或生成期间禁止修改、保存、清除和测试。
- 成功文案为“连接及模型调用成功”，只代表该次测试，不承诺模型回答准确率或所有参数可用。

### 11.2 持久化契约

用户已明确选择：本机保存问题与回答，重开插件仍可查看，不保存快照、证据和 Key。

- 使用已有 `chrome.storage.local`，独立键前缀 `aiHistory.v1.`，每个会话生成独立 UUID；不序列化 `AiSession` 或请求体，不覆盖已有模型设置/Key 存储策略。
- 每条会话历史只保存版本、ID、名称、创建/更新时间及问答列表。每轮问题保存 `question.text / question.createdAt`，回答保存 `answer.text / answer.status`，另有轮次 ID 与模型名称。问题与回答是独立字段，可分别复制；不存 Base URL、错误响应体、单据/页面绑定、快照、证据、Trace、认证头或 Key。
- 持久化前再次过滤凭据文本，并替换当前面板实际请求使用过的 Key；这些 Key 集合仅留内存。问答正文可能自然包含回答中描述的业务内容，不额外保存来源证据附件。
- 发送进入生成时保存问题；流式正文每 1.5 秒做一次保存，完成、停止、关闭会话及重命名时立即发起保存。同一会话写入串行，防止旧片段覆盖最终回答。不同面板创建的会话使用独立键，避免相互覆盖。
- 流式检查点按“未完成/已停止”保存；面板意外退出后不显示为仍在生成。不保证崩溃或强制重载前尚未落盘的最后一段文本可恢复；已经成功保存的内容可以恢复。
- 存储失败/额度不足时保留当前面板内问答并提示失败；关闭错误提示后仍可在历史页“重试保存”。不静默截断问答或自动删除旧记录。读取失败保留原存储，支持手动重新读取。
- 空会话、未发送草稿和仅准备失败的问题不进入持久化历史；首个问题已提交后的停止、失败及部分回答会保存。已有旧版本内存历史无法在面板已关闭后追溯恢复。

## 14. 删除问答历史（2026-09-17）

- 历史详情新增“删除此会话历史”，显示具体会话名称及影响，用户点击“确认删除”后清除该会话全部持久化问答；“取消”不修改内容。本轮实现删除功能，不直接删除用户现有数据。
- 删除成功后更新列表和当前选择；没有记录时显示空态。删除失败保留记录并提供错误提示，可再次删除；若删除期间生成了新回答，保留最新内容供重试保存。

- 刷新历史以本机记录为准，其他面板删除的旧记录不会仅因当前内存缓存而重新出现在列表。删除过程中禁止重复删除和刷新。
